# 小手机 · 学习文档

> 面向：想用一台手机做出自己「小手机」的人。
> 不需要会编程，全程只在浏览器里点。
> 对应当前代码（内核 v0.1）；实现细节以 [Wiki](wiki/README.md) 为准。

---

## 写在前面

小手机不是"一个聊天软件"，它是一台**假装成手机的操作系统**：

- **桌面**是它的门面，可以换成格栅、侧边栏、或者带 Dock 的手机桌面
- **应用**是场景：消息、通讯录、商店，以后还会有淘宝、地图、小游戏
- **人物**住在里面，有头像、人设、开场白，还会记事

你做的不是"从零写代码"，而是**装一台手机，再决定它长什么样、住着谁**。

---

# 第一部分 · 做出你的第一台

## 1. 你只需要三样东西

| 东西 | 用途 |
|---|---|
| 一部安卓手机 | 全部操作都在手机上完成 |
| 浏览器 | 看效果、改配置 |
| 一个能起本地服务的小工具 | 框架已经带了，一条命令 |

不需要：电脑、Node、命令行经验、API 密钥（先玩演示模式）。

## 2. 三个文件

学员最终拿到的一台小手机，内容就是三样：

```
index.html     三行，把框架引进来
app.json       人设、配色、装哪些应用
assets/        头像、壁纸这些图片
```

> 这是分发包的目标形态。当前开发仓库不是这三个文件，还包含内核 `core/` 和模块 `modules/`。

`app.json` 长这样：

```json
{
  "app": { "title": "我的小手机" },
  "shell": "shell.grid",
  "apps": ["app.chat", "app.store", "app.settings", "app.contacts"],
  "features": ["memory.simple"],
  "characters": [
    {
      "id": "ayan",
      "name": "阿岩",
      "runtime": "runtime.chat",
      "greeting": "……你来了。",
      "persona": { "prompt": "你叫阿岩，说话很慢，嘴硬心软。", "traits": ["慢热"] }
    }
  ]
}
```

**注意：这里面没有 API 密钥。** 密钥只存在你自己的浏览器里，所以这个文件发给谁都不怕。

## 3. 打开它

在项目目录里跑：

```bash
python3 -m http.server 8770
```

然后浏览器打开 `http://127.0.0.1:8770/`。

这就是全部。改完文件刷新页面就是最新，**没有构建、没有打包、没有 npm install**。
（只有跑 `tests/` 时例外：需要 `cd tests && npm ci` 安装测试依赖，它不参与应用运行。）

## 4. 换个人物

打开 **通讯录** → 「＋ 新建」：

- 名字、头像（填一个表情或图片地址）
- 人设：这个人是谁、怎么说话、在意什么
- 开场白：打开对话时它说的第一句话
- 脑子：现在只有"普通陪聊"，以后会有咨询师、助手

保存后回到 **消息**，它就出现了。删掉一个人，他的聊天记录不会跟着删。

## 5. 换个桌面

打开 **商店** → 「桌面」一栏，三个外壳点一下原地换：

| 外壳 | 样子 |
|---|---|
| 格栅桌面 | 朴素方块网格，默认 |
| Asael 桌面 | 玻璃质感图标 + 底部 Dock |
| 侧边栏 | 左边一列，右边内容 |

换的时候**不刷新页面**，商店自己还开着。

## 6. 换个颜色

商店 → 「主题色」，当前有 101 套：墨黑、米白、苔绿、暮紫、沙、霓虹，以及
深邃 / 清新 / 莫兰迪 / 糖果 / 东方等系列。

点一下**立即生效**，连重装都不用。桌面、聊天、设置、商店会一起变色——
因为所有颜色都走同一套变量，谁也没有自己的私有配色。
（只给四个基础色的主题，其余中性层由 `core/tokens.js` 自动推导。）

## 7. 让它记事

装好「简单记忆」之后，桌面上会多一个 🧠 **记忆**：

- 每聊 **3 轮**，它把最近的对话压成一条记忆（按人物分开存）
- 每次开口前，挑 **4 条**最相关的带进对话
- 记忆页里能看全部、单条删、全部清空

三个数字都能在 **设置 → 记忆** 里改。

## 8. 换个背景

背景是**三个独立的 App**，不是点桌面空白处弹出的面板：

1. 先到商店「应用」里安装其中一款（它们带有「背景」类目标签）：
   - **主题色背景**：纯色 / 渐变 / 光晕 / 双光 / 方格 / 点阵，全部跟着主题色走
   - **图片背景**：从本地选一张，能调滤镜、模糊、透明度（保存前压到 1440 长边）
   - **自定义背景**：自己写几行 CSS 声明，模板里有能用的颜色变量
2. 桌面上会多一个图标，点开就是编辑器。
3. 打开哪一款，当前背景就切到哪一款；三款共用一层背景，后开的会顶掉前一个。

当前没有「点桌面空白处换背景」的交互，也没有「跟随主题色」按钮；
卸下背景 App 后，桌面会露出主题自带的壁纸。

# 第二部分 · 它是怎么运作的

## 五个概念

| 概念 | 一句话 | 谁负责 |
|---|---|---|
| 容器 | 那台"手机"的壳子 | 内核 |
| 外壳 | 桌面长什么样 | 模块 |
| 应用 | 桌面上的一个图标 | 模块 |
| 脑子 | 一个角色怎么运转 | 模块 |
| 管线 | 每次开口前，把哪些信息拼给模型 | 内核 |

## 一个应用是怎么出现在桌面上的

```
app.json / 商店
      ↓
   App 注册表        ← 唯一一条线
      ↓（订阅）
   外壳重画
```

关键点：**外壳订阅注册表，而不是启动时拿一份名单。**
所以任何模块在任何一个时刻注册一个应用，桌面都会自己长出来。

## 商店为什么不会弄坏你的东西

商店**不改你的 `app.json`**，只在你自己浏览器里记两件事：

- **加了谁**（从商店装的）
- **删了谁**（你卸掉的）

生效的应用 = `app.json` 里的 − 你删掉的 + 你后来装的。

这样以后框架给你加了新应用，你一刷新就能看到，不会被"你以前的旧名单"挡住。

## 为什么模块可以乱拆

模块之间**不许互相 import**，只能通过三条通道说话：

- **数据**：每个模块只能写自己的仓库
- **事件**：只能广播，不能回调
- **提示词**：大家往同一条管线里投段落，内核负责裁剪

所以拆掉任何一个模块，别的模块顶多少一个功能，不会崩。

# 第三部分 · 做自己的模块（进阶）

## 最小形状

```
modules/app.你的名字/index.js
```

```js
export default {
  id: 'app.你的名字',
  kind: 'app',          // shell | app | runtime | feature | ui（ui 只有样式，没有 mount）
  api: '1.x',
  meta: { name: '名字', icon: '▦' },
  css: 'style.css',     // 可选，自带样式
  mount(body, ctx, api) {
    body.append(ctx.ui.h('div', {}, '你好'));
    return { destroy() {} };
  },
};
```

然后在 `store.json` 的 `modules` 里加一条，商店里就出现了。

## 三条禁忌

1. **不要 import 内核文件**，要能力就从 `ctx` 拿
2. **不要写别人的数据**，只用 `ctx.vault.namespace('自己的名字')`
3. **不要写死颜色**，用 `var(--accent)` 这些变量，否则换主题时你会是唯一没变的那个

## 上架前

- `api` 写 `1.x`
- 带 `mount` 的模块要返回 `destroy()`，把定时器、监听都清掉
- 自带 `css`，不要把样式塞进内核
- 数据要能整体导出（当前备份是整份 JSON；按模块 schema 迁移仍是规划，未实现）

# 附录 · 我们踩过的坑

| 坑 | 怎么绕 |
|---|---|
| 图片直接塞本地存储，几下就爆 | 上传前先缩到 1440 长边，存 JPEG（图片背景已实现；人物头像上传仍是规划） |
| 手机上 `:hover` 会粘住 | 只在 `@media (hover: hover)` 里写 |
| 切后台回来消息丢了 | 目标做法是请求可中断可续、失败指数退避；当前只实现了中断，重试/续传仍是规划 |
| 手机不点一下不许自动播放 | 首次播放必须由一次点击触发（语音模块目前尚未实现） |
| 上下文越聊越贵 | 提示词有总预算，超了自动裁旧 |
| 记忆越记越多拖慢 | 按人物隔离，定期压缩，能手动删 |
| 换主题只换了一半 | 所有颜色走同一套变量，禁止硬编码 |
| 换外壳只有排布变了 | 外壳必须自带整套桌面样式 |
| 新装的应用不显示 | 商店只记"加了谁/删了谁"，不存整份名单 |
