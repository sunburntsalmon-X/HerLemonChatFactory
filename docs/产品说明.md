# 小手机框架 v1 · 功能版

> 一句话：你在做的是一个**角色扮演用的手机操作系统**。
> 系统（框架）+ 应用（模块）+ 内容（学员自己写的）。

> **文档性质：v1 产品蓝图，不是当前完成度。**
> 本文描述的是目标形态；截至 2026-11-19，代码只落地了其中一部分（见下方现状表）。
> 具体实现以 [Wiki](wiki/README.md) 和代码为准。文中标「规划」的章节尚未实现。

## 一、三层结构

| 层 | 是什么 | 谁来做 | 学员要不要懂 |
|---|---|---|---|
| 系统 | 桌面、App 切换、聊天、数据、皮肤 | 你 | 不用懂 |
| 应用 | 淘宝、地图、银行、游戏、语音、生图 | 你 + 合作伙伴 | 勾选即可 |
| 内容 | 人设、世界书、剧情、图标壁纸 | 学员 | 只用这个 |

判断标准：**换个角色、换套皮还得在的东西，进系统；只有某个 App 才要的，做模块。**

## 二、系统里必须有的八件（v1 目标；括号内为现状）

### 1. 桌面壳（外壳已实现；状态栏/电量/信号未实现）
图标网格、壁纸、状态栏（时间/电量/信号）。状态栏显示的是假数据，但要走真机时间，不然一眼穿越。
当前三种外壳都没有状态栏，内核也明确不做「假手机」元素。

### 2. 应用容器（打开/返回已实现；记住上次位置、切后台未实现）
点图标进 App，返回键回桌面，能记住上次停在哪。所有 App 共用一套"进入/返回"的动作，不然每个 App 的返回逻辑都不一样，学员会疯。

### 3. 人物与联系人（人物 CRUD 已实现；图片压缩/上传未实现）
角色列表就是通讯录。一个人物 = 名字 + 头像 + 人设 + 口癖 + 关系。头像和立绘走图片压缩，不能直接塞原图。

### 4. 聊天内核（流式/中断已实现；重发/失败重试未实现）
流式出字、中断、重发、失败重试。这是整个产品最核心也最容易崩的地方。

### 5. 记忆与世界书（简单记忆已实现；世界书未实现）
决定"它为什么记得你上次说的话"。这里包括长期记忆的沉淀、召回，和世界书的关键词触发。**这是最值钱的一块，也是最容易做烂的一块。**

### 6. 本地存储与备份（存储/导入导出已实现；导入暂存区与 schema 迁移未实现）
所有对话、人物、图片都存在浏览器里。备份是导出成一个文件，换手机能带走。

### 7. 设置（已实现）
填 API、选模型、选语言、清缓存。学员第一次打开就得能用，不能让他改代码。

### 8. 皮肤系统（主题/按钮/弹窗/字体已实现；气泡包/图标包/音效包未实现）
气泡样式、配色、圆角、字体。换一套皮，整个手机的性格就变了。

## 三、做成模块的（规划；当前只有记忆模块与背景/界面皮肤）

语音朗读、语音输入、生图、日历、相册、地图/线下模式、小游戏（打牌/狼人杀/你画我猜）、跑团、世界书编辑器、浏览器。

学员勾一个就多一个 App 图标，不勾就完全不加载，不占体积。

## 四、素材包（规划，未实现）

图标包、壁纸包、音效包、气泡包。**你的合作伙伴大多应该走这条路**，不需要会编程，交 JSON + 图片就行。这也是商城最容易做起来的部分。

## 五、新手必踩的坑（目标：框架替你填平；部分能力仍在规划）

这一节是框架存在的理由，比功能清单更重要。

| 功能 | 新手会踩的坑 | 框架里替你做什么 |
|---|---|---|
| 聊天 | 切后台回来消息丢了 / 断网重试导致重复扣费 / 上下文越聊越贵 | 请求可中断、超 token 自动裁旧（已实现）；失败重试/指数退避、切后台续传（规划） |
| 备份 | 图片塞进 localStorage 直接爆 / 导出忘了带图 / 导入覆盖不提示 | 图片存 IndexedDB、整体导出（已实现）；导入前自动备份旧数据、缺失模块暂存（规划） |
| 语音 | 手机上不点一下就不许自动播放 / 切后台朗读被掐断 / 长文一口气读崩溃 | 首次播放强制要一次点击、按句分段、切后台自动暂停 |
| 生图 | 图太大撑爆存储 / 失败就一直转圈 / key 被写进代码 | 统一压缩到指定尺寸、超时给兜底图、key 只存本地 |
| 记忆 | 越记越多最后拖慢 / 记错了还改不掉 / 串到别的角色身上 | 按角色隔离、定期压缩摘要、可在设置里删改 |
| 世界书 | 触发词一多就撑爆 token / 优先级打架 | 按预算截断、同优先级按最近使用排序 |
| 桌面 | 图标一多就卡 / 壁纸大图吃内存 | 图标虚拟化、壁纸限制尺寸 |
| 皮肤 | 换皮之后某个 App 没跟着变 | 所有颜色走同一套变量，禁止硬编码 |

## 六、明确不做（v1）

多人联机、真实联网的淘宝/地图（假的更好）、云同步账号、付费系统、打包 APK、世界书导入 SillyTavern 角色卡。

写在这里是为了挡需求，不是为了以后都做。

## 七、体积边界（目标）

- 系统本体：小（几十 KB），首屏秒开
- 每个模块：独立加载，勾了才下
- 学员的仓库：三个文件（`index.html`、`app.json`、素材目录），不超过 300 行

## 八、学员的仓库长什么样（目标形态；当前仓库不是三文件，含完整的 core/ 与 modules/）

```
index.html        三行，引框架
app.json          人设、配色、勾了哪些 App
assets/           头像、壁纸、图标
memories/         记忆，由 AI 助手写
```

学员全程只改 `app.json` 和素材。**API 密钥不写在里头**，只存在他自己浏览器里，所以仓库公开也不怕。

## 九、你自己的施工顺序（路线图，非完成度）

1. 桌面壳 + 设置 + 聊天内核 —— 能自己跟自己聊起来
2. 人物 + 记忆 + 备份 —— 能长期用下去
3. 皮肤 + 三个模块（语音、生图、日历）—— 有"手机"的感觉
4. 素材包 + 商城清单 —— 合作伙伴能进场
5. 开课

前两步做完，就已经能教第一批学员了。
