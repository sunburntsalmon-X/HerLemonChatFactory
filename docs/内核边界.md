# 小手机 · 内核与契约（v1）

> 框架只保留"所有小手机都跑不掉的东西"，其余全部可换。
> 内核约 1500 行（当前 `core/*.js` 约 1481 行），模块按需加载。
>
> **文档性质说明：** 本文的架构原则仍然有效，但部分能力属于目标设计、尚未实现。
> 各节已标注「已实现 / 未实现 / 规划」。当前代码以 [Wiki](wiki/README.md) 为准。

## 一、内核七件事

| # | 名字 | 干什么 | 为什么必须在内核 |
|---|---|---|---|
| 1 | `boot` | 启动、读配置、装配模块、出错兜底 | 谁都要先启动 |
| 2 | `host` | 应用容器：挂载、页面栈、卸载（切后台未实现） | 任何外壳都要装 App |
| 3 | `vault` | 数据仓：命名空间、导入导出、清空（版本/迁移未实现） | 备份的唯一入口 |
| 4 | `llm` | 模型通道：流式、中断（重试/计费保护未实现） | 所有智能功能共用 |
| 5 | `prompt` | 提示词管线：拼装、预算、裁剪 | 记忆/世界书/人设的唯一交汇处 |
| 6 | `bus` | 事件与配置：广播、设置项注册表 | 模块之间唯一的嘴 |
| 7 | `tokens` | 外观令牌：颜色、圆角、字体的变量表 | 换皮不改代码 |

注意：**内核里没有"聊天"这个功能**。聊天是一个模块。

## 二、可以整块换掉的东西

| 东西 | 举例 | 谁来做 |
|---|---|---|
| 外壳 `shell` | 手机格栅桌面 / 侧边栏（你的） / 极简列表 | 你 |
| 角色脑子 `runtime` | 纯聊天（已实现）/ 心理咨询 / 全能助手（接 MCP）（后两者规划） | 你 + 第三方 |
| 聊天 `app.chat` | 单聊 / 群聊 / 跑团式长文 | 你 |
| 记忆 `memory` | 简单版（你的） / 向量库 / 工坊式 | 你 + 第三方 |
| 世界书 `lorebook` | 关键词触发 / 常驻设定 | 你 |

这套设计的核心是：**角色的数据是固定的，角色的脑子是可换的。**

## 三、三条通道（模块之间唯一的合法接触）

```
        ┌──────────────┐
        │   内核       │
        │ vault bus    │
        │ prompt       │
        └──┬───┬───┬───┘
     数据 │事件│提示词│
        ┌──▼───▼───▼──┐
        │  各个模块    │
        └─────────────┘
```

1. **数据**：每个模块有自己的命名空间（`memory.simple`、`app.calendar`），只能读写自己的，绝不碰别人的。
2. **事件**：单向广播（如 `chat:replied`、`app:opened`、`settings:changed`），不许回调、不许同步递归。
3. **提示词**：模块往里"投段落"，内核统一裁剪拼装。

**硬规矩：模块之间禁止直接 import，禁止互相持有引用。** 这条守住了，拆任何一个模块都不会把别人带崩。

## 四、角色的统一形状

```json
{
  "id": "ayan",
  "name": "阿岩",
  "avatar": "assets/ayan.webp",
  "runtime": "runtime.chat",
  "persona": { "prompt": "说话很慢，嘴硬心软", "traits": ["慢热"] },
  "greeting": "……你来了。"
}
```

`runtime` 这一个字段决定了这个角色的"脑子"：
- `runtime.chat` —— 普通陪聊（当前唯一已实现）
- `runtime.counselor` —— 心理咨询，每轮先共情再提问（规划）
- `runtime.agent` —— 全能助手，能调工具、接 MCP（规划）
- `runtime.trpg` —— 跑团主持（规划）

学员换一个值，角色的行为模式就换了，人设和头像都不用动。

## 五、提示词管线（解决"记忆和世界书怎么联动"）

每个模块往管线里投一个"段落"，声明三件事：**优先级、最多占多少、内容**。

内核按优先级排序，按总预算从上往下装，装不下就截断靠后的。设置里能看到已装入的段落、每段署名和截断标记（被预算丢弃的段暂不显示）。

这样能一并解决三个老问题：
- 世界书触发词一多就撑爆 token → 预算截断，谁都超不了
- 记忆和世界书抢位置 → 优先级说了算
- 出问题查不出来 → 每一段有署名

## 六、备份（最难的那块）

> 本节是目标设计。当前实现只有「整体导出 → 导入时先清空再覆盖」，
> 没有暂存区、schema 迁移或版本拦截（见 [Wiki 05](wiki/05-数据与备份.md)）。

难点不是导出，是**导回来的时候，有些模块已经不在**。

目标导出格式：

```
备份文件
├── app.json          学员的配置
├── core.json         人物、设置
├── modules/
│   ├── memory.simple.json    { schema: 1, rows: [...] }
│   └── app.calendar.json     { schema: 2, rows: [...] }
└── assets/           图片
```

目标设计中，导入时按三种情况处理（**均未实现**）：
- **模块不在** → 数据进"暂存区"，留着不删，等他装回那个模块
- **schema 旧** → 跑模块自带的迁移函数
- **schema 新** → 提示"请先升级"，绝不覆盖

当前实际行为：`vault.importAll(data, { merge: false })` 先清空本机数据，再按命名空间整体写入，
然后刷新页面；模块是否缺失、schema 版本都不检查。

目标规矩：**模块不声明 schema 和迁移函数，不许上架。** 这一条能挡掉未来 90% 的"导入后数据乱了"。

## 七、设置页自动生成

模块自己声明"我有这些设置项"，内核自动画出来。学员看到的是勾选框和输入框，不是代码。

内核注册两组：模型（API/接口/模型/密钥）、外观（强调色/圆角）；「数据」分组由 `app.settings` 自己绘制。
模块还可以注册自己的设置组，设置页会一并生成。

## 八、外壳怎么换

`shell` 只干三件事：画桌面、画图标、把点击变成"打开某个 App"。其余都由 `host` 负责。

所以你的侧边栏、别人的格栅桌面，在内核眼里是同一个东西。

## 九、上架契约（防 bug 的硬规矩）

1. 只能通过 `ctx` 拿能力，不许直接引用内核文件
2. 声明 `api: "1.x"`，版本不符直接拒绝加载
3. 只写自己的数据命名空间；schema 与迁移目前没有强制机制（目标约定，尚未落地）
4. 带 `mount` 的模块必须返回 `destroy()`，能干净卸掉（当前约束是 `destroy`，不是 `uninstall`）
5. 不许在启动阶段做耗时操作（超过 100ms 就得延后）
6. 模板自带一份测试，上架前跑通

## 十、分三期，别一次做完

**v0（能跑，已实现）**：`boot / host / vault / llm / prompt` + `shell.grid` + `app.chat` + 设置
**v1（能用，部分实现）**：角色 runtime 分家（仅有 `runtime.chat`）+ `memory.simple` + 备份导入导出（无迁移/暂存）
**v2（能卖，部分实现）**：商城清单（已有）+ 素材包（规划）+ 第三方模块（规划）+ 侧边栏外壳（已有）

v0 的目标很具体：**换一个外壳、换一个角色，聊天照常跑。** 这两件事能跑通，说明抽象是对的；跑不通，说明还抽象得不够。
