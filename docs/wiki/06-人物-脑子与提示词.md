# 06 · 人物、脑子与提示词

相关文件：`core/people.js`、`core/prompt.js`、`core/llm.js`、`modules/runtime.chat`、`modules/app.contacts`、`modules/app.chat`。

## 角色（人物）的固定形状

```json
{
  "id": "ayan",
  "name": "阿岩",
  "avatar": "",
  "runtime": "runtime.chat",
  "greeting": "……你来了。坐吧。",
  "persona": {
    "prompt": "你叫阿岩，二十六岁，在一家旧书店打工……",
    "traits": ["慢热", "嘴硬", "记性好"]
  }
}
```

| 字段 | 作用 | 备注 |
|---|---|---|
| `id` | 唯一标识 | 聊天记录键 `conv:<id>`、记忆键 `items:<id>` 都用它 |
| `name` | 显示名 | 也用于头像占位字 |
| `avatar` | 头像 | 空、一个表情，或 `http(s):` / `data:` / `./` / `../` 开头的图片地址 |
| `runtime` | 角色脑子模块 id | 缺省按 `runtime.chat` |
| `greeting` | 开场白 | 首次进入对话时作为一条 assistant 消息写入 |
| `persona.prompt` | 人设正文 | 由 runtime 模块拼进提示词 |
| `persona.traits` | 性格关键词 | 通讯录里用「、」「,」「，」分隔 |

头像判定逻辑在 `app.chat` 与 `app.contacts` 中各有一份：

```js
const isImage = /^(https?:|data:|\.\/|\.\.\/)/.test(raw);
```

不是图片地址时，取 `avatar` 或 `name` 的第一个字符（按 Unicode 码点切分）。

## `people`：出厂人物 + 本机人物

```js
const people = createPeople({ vault, config, bus });
await people.load();
```

行为：

- `config.characters` 是出厂人物（来自 `app.json`）。
- 本机 `core/characters` 存在数组时，以本机为准；否则用出厂人物。
- `list()` 返回浅拷贝，避免调用方改到内部数组。
- `add()` 未给 `id` 时生成 `c<时间戳后 6 位>`。
- `update()` 按 id 合并补丁。
- `remove()` 只从人物列表移除，不删聊天记录。
- `reset()` 删除 `core/characters`，回到出厂人物。
- 所有写操作都会发 `people:changed`；聊天的会话列表订阅它，所以新建人物后消息页立刻多一行，不需要刷新。

通讯录 `app.contacts` 只负责表单和调用 `people.*`；它不直接读写 `vault`。

## `runtime`：角色的脑子

```text
人物的 runtime 字段 → boot 收集去重 → 逐个 loadModule → setup(ctx)
```

- 当前只有一个：`runtime.chat`。
- `runtime` 模块不画界面，只在 `setup` 里向提示词管线注册段落。
- 通讯录编辑页的「脑子」下拉框来自 `ctx.market.list('runtime')`，清单里新增 runtime 模块后自动多一项。
- 角色数据固定、脑子可换：换 `runtime` 不需要改人设和头像。

新增 runtime 的模板见 [11-模块开发指南](11-模块开发指南.md)。

## 提示词管线

### 贡献者形状

```js
ctx.prompt.register({
  id: 'memory.simple',   // 必填，用于署名与排查
  priority: 70,          // 越大越靠前，默认 50
  maxChars: 400,         // 单段最多多少字，默认 600
  when: (c) => true,     // 可选，条件不满足就不参与
  build: (c) => '……',    // 返回这一段文字
});
```

`build` 收到的上下文对象由调用方决定。当前 `app.chat` 传入：

```js
{
  character,            // 当前人物
  history,              // 最近 N 轮消息（role/content）
  userText,             // 最后一条用户消息
  settings: ctx.settings,
}
```

### 排序与裁剪

`prompt.build(ctx, budget = 2000)`：

1. 过滤 `when` 为假的贡献者。
2. 按 `priority` 降序排序。
3. 每段 `build()` 后 `trim()`，并按自己的 `maxChars` 截断。
4. 按总预算 `budget` 从上往下装：
   - 剩余空间不足时截断当前段并标记 `truncated`；
   - 空间为 0 的段进入 `dropped`，原因 `超出预算`。
5. 用两个换行连接 `kept` 段的文本，得到 `system`。

返回结构：

```js
{
  system,    // 最终拼出的 system 文本
  parts: [{ id, text, maxChars, truncated }],
  dropped: [{ id, text, maxChars, reason }],
  budget,
  used,
  at,
}
```

`prompt.reset()` 会把贡献者和最近一次拼装都清空；重装时不清会让人设拼两遍。

### 当前贡献者

| 贡献者 | priority | maxChars | 条件 | 内容 |
|---|---|---|---|---|
| `runtime.chat` | 90 | 700 | 人物 runtime 是 `runtime.chat` | 人设 + 性格关键词 + 口语化回复要求 |
| `memory.simple` | 70 | 400 | 有记忆时 | 「你记得这些事」+ 最多 N 条记忆 |

世界书（lorebook）尚未实现；它未来也应该是一个贡献者，而不是在聊天应用里拼字符串。

### 预算来源

`app.chat` 每次回复前：

```js
const budget = Number(ctx.settings.get('ai.params.maxChars', 2000)) || 2000;
```

默认 `app.json.ai.params.maxChars = 2000`。中文大致按 1 字 ≈ 1.5 token 估算。

### 查看拼装结果

设置 → 数据 → 「查看提示词拼装」：

```text
总预算 2000 字，用了 xxx 字

【runtime.chat】
……
【memory.simple】（已截断）
……
```

它读取 `ctx.prompt.lastBuild()`。当前界面只显示 `parts`，不显示 `dropped`；如果怀疑预算不够，需要在控制台或代码里看完整对象。

## 聊天上下文怎么取

`app.chat` 的 `reply()`：

```js
const turns = Number(ctx.settings.get('apps.chat.turns', 12)) || 12;
const history = messages.slice(-turns * 2).map(({ role, content }) => ({ role, content }));
```

- 「轮」按一对用户+助手消息计算，所以默认 12 轮 = 最近 24 条。
- 只把 `role` / `content` 传给模型，`ts` 不传。
- `system` 由提示词管线生成。
- 开场白也作为 assistant 消息存在历史里。

## `llm`：模型通道

```js
for await (const piece of ctx.llm.stream({
  character,
  messages,
  system,
  signal,
})) {
  // 逐段渲染
}
```

### 走哪条路

```text
provider === 'mock' 或没有 key  → mockStream（本地演示）
否则                            → openaiStream（OpenAI 兼容接口）
```

### OpenAI 兼容路径

- 地址：`<baseUrl 去掉尾部斜杠>/chat/completions`
- 请求体：

```json
{
  "model": "...",
  "temperature": 0.9,
  "stream": true,
  "messages": [{ "role": "system", "content": "..." }, "...history"]
}
```

- 请求头：`Authorization: Bearer <key>`。
- 解析 SSE：只处理 `data:` 行，跳过 `[DONE]`，读取 `choices[0].delta.content`。
- 不完整行会留在 buffer，等下一次读取。
- 非 2xx 抛错：`接口返回 <status>：<前 120 字>`。
- 不支持流式（没有 `res.body`）抛错。
- **没有自动重试、退避、计费保护**；中断由调用方 `AbortController` 负责。

### 演示模式

`mockStream` 的规则：

| 输入 | 回复 |
|---|---|
| 空文本 | `嗯？` |
| 以 `?` 或 `？` 结尾 | `（名字停顿了一会儿）\n你说的这个，我得想想。\n你自己是怎么想的？` |
| 少于 4 个字符 | `嗯。你说。` |
| 其他 | `「前 16 字」` + 随机一句收尾（我记着了 / 你先别急着下结论 / 这话你以前没说过 / 行，我知道了） |

分块长度为 1–3 个字符，每块延迟 22–62ms；这模拟打字效果，不是真模型输出。

### 中断与错误

- 聊天应用在离开对话或销毁时 `abort.abort()`。
- 演示模式与真实流都会检查 `signal.aborted`；中断时抛 `AbortError`。
- `app.chat` 把中断显示为已收到的部分或「（已中断）」，其他错误显示「（出错了：...）」并标红边框。
- 出错时若已收到部分文本，仍会保存已收到的内容并发 `chat:replied`。

## 设置项

内核注册两组：

| 组 | 字段 | 说明 |
|---|---|---|
| `core.ai` | `ai.provider` | `mock`（演示模式）/ `openai`（OpenAI 兼容） |
|  | `ai.baseUrl` | 如 `https://api.deepseek.com/v1` |
|  | `ai.model` | 如 `deepseek-chat` |
|  | `ai.key` | 密码框，写 `core/ai.key` |
| `core.theme` | `theme.accent` | 强调色覆盖；会盖过主题自带色 |
|  | `theme.radius` | 圆角 6–36 |

模块还能注册自己的组，例如消息的「带几轮」、记忆的三个数字。

## 想扩展时

- **换一种角色行为**：新增 `runtime.*` 模块，注册自己的提示词段，把人物的 `runtime` 指向它。
- **加世界书**：新增 feature 模块，注册高优先级提示词段，按关键词/场景拼内容。
- **换模型服务**：当前只支持 OpenAI 兼容的 `/chat/completions`；其他协议需要改 `core/llm.js` 或在模块里另建通道。
