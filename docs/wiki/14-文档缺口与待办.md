# 14 · 文档缺口与待办

这一页记录三件事：

1. 现有文档各自覆盖了什么、哪些还可用；
2. 旧文档与当前代码明显不一致的地方；
3. 代码里已经能确认的待办与实现风险。

> 本页的依据是当前 `main` 分支代码。旧文档不在这里直接改，避免影响既有读者；以本 Wiki 为准。

## 二、明确的文档与代码矛盾

### 1. `README.md` 的目录树

- 列了 `core/ui.js`（公共控件、状态栏），实际不存在该文件；相关能力在 `core/dom.js` 和 `core/sheet.js`。
- 漏了 `core/apps.js`、`core/sheet.js`。
- 内核明确「不做假手机」，没有状态栏；状态栏只可能由外壳实现。

### 2. 主题数量

- `README.md` 商店小节：主题色「六套」。
- `docs/学习文档.md`：同样写六套：墨黑、米白、苔绿、暮紫、沙、霓虹。
- 实际 `store.json.themes` 有 **101 套**；前 6 套是完整 9 色，后 95 套是四色数据。

### 3. 测试数量

- `README.md`「已验证」只列 4 个测试。
- `AGENTS.md` 写「这九条必须还是全绿」。
- `docs/接活单.md` 也写「九条验收」。
- 实际 `tests/package.json` 串行跑 **11 个**：smoke、swap、market、contacts、memory、wallpaper、registry、stale、ui、shop、sheet。

### 4. 内核行数

- `AGENTS.md`「内核红线」：`core/` 的 JS 控制在 1500 行以内（现在 1253）。
- 实际 `core/*.js` 合计约 **1481 行**，仍在上限内，但余量只有约 19 行。新增内核功能前应优先考虑模块化。

### 5. 桌面空白处换背景

- `docs/学习文档.md`：点桌面空白处弹出背景面板，三种背景可选。
- 实际没有该交互；背景是三款独立 App，需要先在商店安装，再点桌面图标进入编辑器。
- `tests/wallpaper.mjs` 明确断言：点 `.stage` 不弹任何东西。

### 6. `fx.wallpaper`

- `docs/学习文档.md` 的 `app.json` 示例里 `features: ["memory.simple", "fx.wallpaper"]`。
- 实际没有 `modules/fx.wallpaper`；旧的背景功能已拆成三个 `fx.bg.*` App，且它们不是 `feature`，而是 `kind: "app"`。
- `tests/stale.mjs` 专门模拟老用户的 `fx.wallpaper` 残留，启动时会被自动清理。

### 7. 商城「内置（默认）」

- `AGENTS.md` 提到 `kind: 'ui'` 的皮肤随时能换回「内置（默认）」。
- 实际商店里没有「内置」条目；回到内核基线的方式是点当前皮肤卡片上的「卸下」。
- `store.json` 里 `ui.button` 的 `tutorial` 也写了「点内置（默认）」，同样与界面不符。

### 8. 商城的「背景」分组

- `app.store` 代码里有「背景」分组，取 `market.list('wallpaper')`。
- 但 `store.json` 里没有任何 `kind: "wallpaper"` 的模块；三款背景是 `kind: "app"` + `category: "background"`，所以显示在「应用」下。
- 这意味着 `market.list('wallpaper')` 与 `setWallpaper` 的“条目选择”路径目前没有 UI 入口，背景切换靠打开对应 App 时写入。

### 9. 备份与「内核边界」的描述

`docs/内核边界.md` 描述了：

- 模块不在时数据进暂存区；
- schema 旧时跑迁移；
- schema 新时拒绝覆盖；
- 导出包含 `app.json` / `core.json` / 按模块分文件 / `assets/`。

实际 `modules/app.settings` 的导出是一个 JSON：顶层 `format/version/at/characters/data`，`data` 是 `vault.exportAll()` 的命名空间分组；导入直接 `vault.importAll(data, { merge: false })`，没有暂存、没有迁移、没有 schema 拦截。

### 10. `docs/内核边界.md` 与 `docs/产品说明.md` 里的规划能力

以下能力在文档里被描述为已有或即将有，但当前代码没有实现：

- `llm` 的重试、指数退避、计费保护；
- `host` 的「切后台」与记住上次停在哪；
- `runtime.counselor`、`runtime.agent`、`runtime.trpg`；
- 世界书 / lorebook；
- 语音、生图、日历、相册、小游戏等模块；
- 头像上传与图片压缩（当前只能填表情或图片地址）；
- 导入暂存区、模块 schema 与迁移。

这些应视为路线图，不是现状。

### 11. `docs/设计原则.md` 的举例

- 说 `ui.sheet` 是一个模块 + 设置里的方向下拉，要拆成四个模块；实际已经拆成 `ui.sheet.bottom/right/left/float`，并带 `category: "sheet"`。
- 说背景三件套没标互斥；实际 `store.json` 已加 `category: "background"`，但 `market.install` 只对 `kind: "ui"` 做同类自动卸载，背景 App 之间仍是“可同时安装、只生效一个背景层”。
- 设置页「弹窗试一下」按钮仍在，用于演示内核弹窗基线；按设计原则它算演示入口，不是配置入口。

### 12. `docs/接活单.md` 000 号

000 号「商城改版」状态写「可开工」，要求封面、作者、更新时间、难度、详情、教程、截图、搜索、分区。

当前 `app.store` 与 `store.json` 已实现：

- 卡片封面/色板、作者、难度点；
- 详情页大封面、作者、更新日期、难度、简介、详细介绍、使用教程、截图；
- 左侧类型目录 + 难度子项；
- 搜索与兜底文案；
- `tests/shop.mjs`。

未完全实现的部分：

- 详情页底部固定主按钮（当前按钮在内容流里）；
- 返回列表保持滚动位置（当前重建列表，未显式保存滚动位置）。

### 13. `AGENTS.md` 的外部引用

`AGENTS.md` 开头引用 `../framework/项目总纲.md`，该文件不在本仓库中；新接手的人无法访问。本 Wiki 不复制其内容，只保留代码内可验证的规矩。

## 三、实现现状与风险

以下不是文档问题，而是读代码时能确认的行为，维护时需要知道。

### 1. 设置快照会覆盖后来的 `app.json` 改动

`settings.set()` 会把除 `characters` 外的整份配置写入 `core/settings`，包括 `apps`、`features`、`shell`。`settings.load()` 又把这份快照深度合并回 `app.json` 默认值（数组直接替换）。

结果：用户改过任意设置或换过主题后，仓库里新加到 `app.json.apps` 的应用可能被本机旧 `apps` 覆盖，不出现。当前测试没有覆盖这条路径。开发时先清空本机数据再验证 `app.json` 改动。

### 2. `memory.simple` 重装后监听叠加

`memory.simple.setup()` 注册 `ctx.bus.on('chat:replied', ...)`，但没有保存取消函数，也没有 feature 级别的卸载回调。每次 `reboot()`（换桌面、装卸应用）都会再次 `setup`，旧监听仍然存在。

可能表现：切换一次桌面后，每轮聊天被计数多次，摘要触发频率变高。新增 feature 模块时不要把“只注册不清理”当成范例。

### 3. 内核行数接近红线

`core/*.js` 约 1481 行，`AGENTS.md` 红线 1500。任何新内核能力都应先评估能否做成模块。

### 4. 商店「背景」分组为空

见上文第 8 条。若要让背景回到「背景」分组，需要把三款模块改成 `kind: "wallpaper"`，或在 `app.store` 里按 `category === 'background'` 取数；这会牵动 `market.list` 与安装逻辑，属于设计决策。

### 5. UI 皮肤缺少「内置」条目

当前只能通过「卸下」回基线。若要做显式「内置（默认）」卡片，需要在 `app.store` 里为 `ui` 分组插入一个伪条目，或在 `market` 里支持 `ui = null`。

### 6. 备份导出里的 `characters` 字段

导出的顶层 `characters` 是 `settings.get('characters', [])`，即 `app.json` 的出厂人物，不是本机修改后的人物。本机人物实际在 `data.core.characters`，所以恢复通常没问题；但如果有工具只读顶层 `characters`，会读到旧数据。

### 7. `host.closeAll()` 不发 `app:closed`

该方法销毁并移除所有层，但不逐个发事件；当前仓库没有调用它。如果未来用它做“回到桌面”，订阅 `app:closed` 的模块不会收到通知。

### 8. `meta.color` 未被消费

模块 `meta` 里的 `color` 目前没有被内核或商店读取；商店封面颜色来自 `store.json` 条目的 `color`（多数条目没有）。不要依赖 `meta.color` 改变桌面图标底色。

### 9. 多 App 层可以叠加

`host.open()` 只追加层，不关闭已有层。桌面入口通常只有一层；如果模块内部再次 `ctx.host.open()`，需要自己管理关闭。

### 10. 测试留下的临时模块

`tests/registry.mjs` 会临时创建 `modules/app.probe` 并在结尾删除。测试中断时可能残留，需手动清理。

## 四、AGENTS 里仍然有效的待办

以下来自 `AGENTS.md`「已知待办」，与当前代码一致：

- 导入时「模块不在 → 暂存区」的逻辑（`vault.importAll` 目前直接覆盖）。
- 人物头像只能填表情或图片地址，还不能上传本地图；要做需要先有图片压缩。
- 记忆只有「最近 + 关键字」召回，没有向量检索；更聪明的记忆应新写 `memory.*` 模块替换。

## 五、维护建议

1. 改代码后同步本 Wiki 的对应页，尤其是 `04`（契约）、`09`（清单）、`10`（主题）、`11`（开发指南）。
2. 旧文档可以在下一次大版本时统一收缩：保留产品定位与历史决策，把操作细节指向本 Wiki。
3. 新增测试时优先覆盖“用户看得见的结果”，并补一条防止本页列出的风险复发的回归测试。
4. `core/styles.css.bak-2026-11-19` 是历史备份，未参与运行、未被引用；保持原样，不要删除或提交为正式样式。
