# 11 · 模块开发指南

相关文件：`core/boot.js`、`core/host.js`、`AGENTS.md`、`modules/` 下任意模块。

## 先选 kind

| 你要做的东西 | kind | 是否占桌面 | 入口 |
|---|---|---|---|
| 桌面长什么样 | `shell` | 桌面本身 | `mount(stage, ctx, { apps })` |
| 一个能点开的 App | `app` | 是 | `mount(body, ctx, api)` |
| 换角色怎么说话 | `runtime` | 否 | `setup(ctx)` |
| 后台功能 / 附带一个 App | `feature` | 否 | `setup(ctx)` |
| 只换外观（按钮/弹窗/字体） | `ui` | 否 | 只有 `css` |

不确定时先问：这个东西是「每个角色/每台手机都需要的机制」还是「某个 App 才要的功能」？前者考虑内核或 feature，后者做成 app。

## 目录与文件

```text
modules/<id>/
├── index.js      必需，export default 模块对象
└── style.css     可选，由模块对象的 css 字段声明
```

`<id>` 必须匹配 `/^[a-z][\w.-]*$/i`，且目录名就是 id。

## 模板

### 1. 应用 App

```js
export default {
  id: 'app.example',
  kind: 'app',
  api: '1.x',
  meta: { name: '示例', icon: '▦', color: '#334455' },
  css: 'style.css', // 可选

  setup(ctx) {
    // 可选：注册设置项、提示词、事件
    ctx.bus.settings.register({
      id: 'app.example',
      title: '示例',
      fields: [
        { key: 'apps.example.count', label: '数量', type: 'number', min: 1, max: 20 },
      ],
    });
  },

  mount(body, ctx, api) {
    const { h } = ctx.ui;
    const store = ctx.vault.namespace('app.example');

    api.setTitle('示例');
    const value = ctx.settings.get('apps.example.count', 3);

    body.replaceChildren(
      h('div', { class: 'settings scroll' },
        h('div', { class: 'group' }, h('h2', {}, '示例'), `当前数量：${value}`)),
    );

    return {
      destroy() {
        // 清定时器、取消 bus 订阅、移除自己挂到 body 之外的节点
      },
    };
  },
};
```

登记：`app.json.apps` 加 id，或在 `store.json.modules` 上架后由用户安装。

### 2. 外壳 Shell

```js
export default {
  id: 'shell.example',
  kind: 'shell',
  api: '1.x',
  meta: { name: '示例桌面' },
  css: 'style.css',

  mount(stage, ctx, { apps }) {
    const { h } = ctx.ui;

    const grid = h('div', { class: 'icon-grid' });
    const root = h('div', { class: 'desktop' }, grid);
    stage.append(root);

    const render = () => {
      grid.replaceChildren(...apps.list().map((app) => h('button', {
        class: 'appicon',
        onclick: () => ctx.host.open(app.id),
      },
        h('span', { class: 'tile' }, app.meta?.icon || '▦'),
        h('small', {}, app.meta?.name || app.id))));
    };

    render();
    const off = apps.on(render);

    return {
      destroy() {
        off();
        root.remove();
      },
    };
  },
};
```

必须自带整套桌面样式（`.desktop`、`.icon-grid`、`.appicon`、`.tile` 等），内核不提供。

登记：`store.json.modules` 加 `kind: 'shell'`；设为默认改 `app.json.shell`。

### 3. 角色脑子 Runtime

```js
export default {
  id: 'runtime.example',
  kind: 'runtime',
  api: '1.x',
  meta: { name: '示例脑子' },

  setup(ctx) {
    ctx.prompt.register({
      id: 'runtime.example',
      priority: 90,
      maxChars: 700,
      when: ({ character }) => character?.runtime === 'runtime.example',
      build: ({ character }) => {
        return [
          character?.persona?.prompt || '',
          (character?.persona?.traits || []).length
            ? `性格关键词：${character.persona.traits.join('、')}。`
            : '',
          '用口语回复，短句。',
        ].filter(Boolean).join('\n');
      },
    });
  },
};
```

登记：`store.json.modules` 加 `kind: 'runtime'`，通讯录的「脑子」下拉框会自动出现；然后把人物的 `runtime` 指向它。

### 4. 功能 Feature（可以自带 App）

```js
export default {
  id: 'example.feature',
  kind: 'feature',
  api: '1.x',
  meta: { name: '示例功能', icon: '✳' },

  async setup(ctx) {
    const store = ctx.vault.namespace('example.feature');

    ctx.bus.settings.register({
      id: 'example.feature',
      title: '示例功能',
      fields: [{ key: 'example.feature.on', label: '开关', type: 'select',
        options: [['1', '开'], ['0', '关']] }],
    });

    ctx.prompt.register({
      id: 'example.feature',
      priority: 60,
      maxChars: 300,
      build: () => '一段会进入提示词的内容',
    });

    const off = ctx.bus.on('chat:replied', () => {
      // 注意：feature 当前没有 destroy 回调，重装会重复注册；
      // 新实现应把 off 存起来，并在模块被卸载时调用（见第 14 页）。
    });

    ctx.host.registerApp({
      id: 'app.example-feature',
      kind: 'app',
      api: '1.x',
      meta: { name: '功能页', icon: '✳' },
      mount(body, _, api) {
        api.setTitle('功能页');
        body.append(ctx.ui.h('div', { class: 'empty-state' }, '内容'));
        return { destroy() {} };
      },
    });
  },
};
```

登记：`app.json.features` 加 id，或在商城安装。

### 5. 界面皮肤 UI

```js
export default {
  id: 'ui.example',
  kind: 'ui',
  api: '1.x',
  meta: { name: '示例皮肤', icon: '▢' },
  css: 'style.css',
};
```

`style.css` 只覆盖内核基线类名，例如：

```css
.btn {
  border-width: 1px;
  border-style: solid;
  border-color: var(--line);
  background: transparent;
  color: var(--fg);
}
```

登记：`store.json.modules` 加 `kind: 'ui'` 和 `category`（如 `button` / `sheet` / `font`）。不需要进 `app.json`；在商城「界面」安装。

## 能力从哪拿

| 想做的事 | 用 `ctx` 的 |
|---|---|
| 建 DOM | `ctx.ui.h(tag, props, ...children)` |
| 提示 | `ctx.ui.toast(text)` |
| 弹窗 | `ctx.ui.sheet({ title, content, side, actions })` |
| 存数据 | `ctx.vault.namespace('<自己的 id>')` |
| 读写设置 | `ctx.settings.get/set` |
| 加设置界面 | `ctx.bus.settings.register` |
| 广播/订阅 | `ctx.bus.on/emit` |
| 拼提示词 | `ctx.prompt.register` |
| 调模型 | `ctx.llm.stream` |
| 打开另一个 App | `ctx.host.open(id)` |
| 注册一个 App | `ctx.host.registerApp(mod)` |
| 读人物 | `ctx.people.list/get` |
| 读商城状态 | `ctx.market.*` |
| 换主题 | `ctx.applyTheme()`（通常不需要直接调） |

## 生命周期与清理

```text
setup(ctx)      每次装配都执行；注册设置/提示词/事件
mount(...)      每次打开都执行；建 DOM，返回 { destroy }
destroy()       关闭或重装时执行
```

- 事件订阅：`const off = ctx.bus.on(...)`，在 `destroy` 或模块卸载时调用 `off()`。
- 定时器：`destroy` 里 `clearTimeout` / `clearInterval`。
- 异步请求：用 `AbortController`，`destroy` 里 abort。
- 状态尽量放在 `mount` 内部；模块顶层变量会在多次打开/重装之间共享（`fx.bg.*` 就用了模块级 `conf`，靠 `setup` 重新加载）。
- `setup` 可能执行多次，`mount` 也可能多次；不要假设只初始化一次。

## 数据与命名空间

- 命名空间用模块 id：`ctx.vault.namespace('app.example')`。
- 键推荐 `类型:标识`，例如 `items:<id>`。
- 不要读写其他模块的命名空间。
- 数据结构要能整体导出（不要存 DOM 节点、函数、循环引用）。
- 当前没有 schema 迁移机制；如果未来需要，必须在模块内自带版本号与迁移逻辑。

## 样式

- 模块自带 `style.css`，并在模块对象里声明 `css: 'style.css'`。
- 只覆盖内核基线类名，类名尽量带模块特征（`.shop-*`、`.sidebar-*`）。
- 不要往 `core/styles.css` 加模块专属样式。
- 颜色只用 CSS 变量，遵守 `:active` / `@media (hover: hover)` 规则。
- 如果模块要往 `stage` 挂背景层：节点加 `data-module-owned`，并在自己负责的范围内清掉旧层。

## 上架到商城

1. 模块代码放 `modules/<id>/`。
2. `store.json.modules` 加条目（字段见 [09-商城与清单](09-商城与清单.md)）。
3. `kind` 与模块对象一致；`category` 决定互斥组（尤其 `ui`）。
4. 写清 `summary` / `detail` / `tutorial`，商店详情页直接展示。
5. 如果希望默认启用，再改 `app.json` 对应字段。

## 测试

1. 新建 `tests/<name>.mjs`，参考现有脚本：JSDOM + `fake-indexeddb/auto` + 本地 `fetch` 桩。
2. 导入 `core/boot.js`，等待 `data-booted="1"`。
3. 用 DOM 查询断言「用户看得见的结果」，不要只断言内部变量。
4. 把脚本加进 `tests/package.json` 的 `test` 链。
5. 单独跑：`node tests/<name>.mjs`。

注意：测试里的 `fetch` 桩只服务本地文件，任何真实网络请求都会失败；需要网络的行为应在演示模式下可验证。

## 自查清单

- [ ] 目录名 = `id`，`api: '1.x'`。
- [ ] `modules/` 下没有 `import` / `require`。
- [ ] 数据只写自己的命名空间。
- [ ] `mount` 返回 `{ destroy }`，清掉事件、定时器、DOM。
- [ ] 外壳/应用图标在桌面可见（`ui` 皮肤除外）。
- [ ] 颜色走变量，标度走 `--sp-*` / `--fs-*` / `--r-*`。
- [ ] 样式在模块自己的 `style.css`，不塞内核。
- [ ] 在 `store.json` 有条目，商城能搜到、能装、能卸。
- [ ] 跑过 `cd tests && npm test`。
- [ ] 更新了受影响的 Wiki 页面（契约、清单、主题）。

## 反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| import 内核文件 | 模块无法独立拆卸 | 从 `ctx` 拿 |
| 启动时存 App 数组快照 | 后加的 App 永远不显示 | 订阅 `apps:changed` |
| 在模块里写死颜色 | 换主题时只有它不变 | 用 CSS 变量 |
| 把 `setup` 当一次性初始化 | 重装后监听叠加、状态错乱 | 清理或幂等 |
| 用全局 `#bg-layer` 但不清理 | 多层背景叠加 | `data-module-owned` + 先删旧层 |
| 功能模块没有可见入口 | 用户不知道装上了什么 | 带一个 App，或在桌面有反馈 |
| 把设置项做成下拉框选择同类方案 | 违反「安装即配置」 | 拆成多个互斥模块 |
