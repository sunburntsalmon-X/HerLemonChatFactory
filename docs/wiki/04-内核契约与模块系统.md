# 04 · 内核契约与模块系统

相关文件：`core/boot.js`、`core/host.js`、`core/apps.js`、`core/bus.js`、`core/prompt.js`、`core/vault.js`、`core/settings.js`、`core/market.js`、`core/people.js`、`core/sheet.js`。

## 四条硬契约

这四条是整个架构成立的前提：

1. **模块不能 import 内核文件**。`modules/` 下不允许出现 `import` / `require`；所有能力从 `ctx` 取。
2. **模块必须声明 `api: '1.x'`**。不匹配 `boot.loadModule` 直接拒绝加载。
3. **数据只写自己的命名空间**。例如 `ctx.vault.namespace('app.chat')`，不要读写别人的前缀。
4. **模块必须能在卸载时清理自己**。有 `mount` 的模块返回 `{ destroy() {} }`，清掉定时器、监听、DOM。

此外还有两条产品级约束（来自 `AGENTS.md`）：

- **模块装完必须在桌面可见**（`kind: 'ui'` 的皮肤例外，它永远在商城「界面」里）。
- **模块自带样式**，只覆盖内核基线类名，不许另起一套全局外观。

## 模块对象的形状

```js
export default {
  id: 'app.example',          // 必填，等于目录名
  kind: 'app',                // shell | app | runtime | feature | ui
  api: '1.x',                 // 必填，当前内核只接受 1.x
  meta: { name: '示例', icon: '▦', color: '#334455' },
  css: 'style.css',           // 可选，模块自带样式
  setup(ctx) {},              // 可选，装配阶段调用
  mount(body, ctx, api) {     // app 必填；shell 的签名不同
    return { destroy() {} };
  },
};
```

### 不同 kind 的差异

| kind | 是否占桌面 | 入口 | 登记位置 | 典型模块 |
|---|---|---|---|---|
| `shell` | 桌面本身就是它 | `mount(stage, ctx, { apps })` | `app.json.shell` 或商城 | `shell.grid` |
| `app` | 是 | `mount(body, ctx, api)` | `app.json.apps` 或商城 | `app.chat` |
| `runtime` | 否 | `setup(ctx)` | 人物的 `runtime` 字段自动加载 | `runtime.chat` |
| `feature` | 否 | `setup(ctx)` | `app.json.features` 或商城 | `memory.simple` |
| `ui` | 否（无图标） | 无 | 商城「界面」安装 | `ui.button`、`font.*` |

补充：

- `feature` 可以用 `ctx.host.registerApp({...})` 自带一个 App，`memory.simple` 就是这样带出「记忆」页的。
- `ui` 模块只有 `css`，没有 `setup` / `mount`。
- `theme` 在旧文档里被列为 kind，但当前主题是 `store.json.themes` 里的数据，不是模块。

## `ctx` API 全表

`ctx` 在 `boot()` 里组装，是模块唯一的能力入口。

### 只读/直接字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ctx.config` | object | `settings.all()` 返回的配置对象引用；`app.json` 默认值 + 本机覆盖后的内存对象 |
| `ctx.stage` | HTMLElement | 外壳挂载的根节点；**只允许背景类模块碰** |
| `ctx.reboot(reopen)` | function | 原地重装；可传重装后要打开的应用 id |
| `ctx.applyTheme()` | function | 重新计算并应用当前主题 |
| `ctx.ui` | object | `{ h, toast, clear, sleep, sheet }` |

### `ctx.settings`

| 方法 | 说明 |
|---|---|
| `get(path, fallback)` | 按点路径读值，如 `get('ai.model', '')` |
| `set(path, value)` | 写值、持久化到 `core/settings`、发 `settings:changed` |
| `reset()` | 回到 `app.json` 默认值，发 `settings:changed`（`path: '*'`） |
| `setKey(secret)` / `getKey()` | 单独存取 `core/ai.key`，不进入普通设置 |
| `all()` | 返回内存中的完整配置对象 |
| `load()` | 启动时把本机存储合并进默认值；模块一般不需要调用 |

### `ctx.bus`

| 方法 | 说明 |
|---|---|
| `on(event, fn)` | 订阅，返回取消函数 |
| `off(event, fn)` | 取消订阅 |
| `emit(event, payload)` | 广播；单个监听器抛错不会影响其他监听器 |
| `settings.register(group)` | 注册设置组，设置页自动生成 |
| `settings.all()` | 读取全部设置组 |

### `ctx.vault`

| 方法 | 说明 |
|---|---|
| `namespace(ns)` | 取命名空间句柄：`{ get(key, fallback), set(key, value), del(key), keys() }` |
| `exportAll()` | 按命名空间分组导出全部数据 |
| `importAll(data, { merge })` | 导入；默认先 `clearAll()` 再写 |
| `clearAll()` | 清空数据库（或 localStorage 里的 `xsj\0` 前缀项） |

### `ctx.prompt`

| 方法 | 说明 |
|---|---|
| `register(contributor)` | 注册提示词贡献者；必须有 `id` |
| `list()` | 当前贡献者的 `{ id, priority, maxChars }` |
| `reset()` | 清空贡献者与最近一次拼装 |
| `build(promptCtx, budget)` | 排序、裁剪、拼装，返回 `{ system, parts, dropped, budget, used, at }` |
| `lastBuild()` | 最近一次拼装结果，供设置页「查看提示词拼装」 |

### `ctx.llm`

| 方法 | 说明 |
|---|---|
| `stream({ character, messages, system, signal })` | 异步生成器，逐段产出文本；无密钥走演示模式 |

### `ctx.host`

| 方法 | 说明 |
|---|---|
| `open(id, params)` | 打开 App；创建页面层、返回键、`api`，调用 `app.mount(body, ctx, api)` |
| `registerApp(mod)` | 把模块注册进 App 注册表（`feature` 自带 App 时用） |
| `setContext(ctx)` | 内核启动时注入；模块不要调用 |
| `isOpen()` | 当前是否有 App 层 |
| `reset()` | 卸载所有 App 并清空注册表；重装前由 boot 调用 |
| `closeAll()` | 关闭所有层（不逐个发 `app:closed`） |

### `ctx.apps`

| 方法 | 说明 |
|---|---|
| `register(app)` / `remove(id)` | 增删 App，发 `apps:changed` |
| `get(id)` / `list()` | 查询 |
| `clear()` | 清空，不单独发事件 |
| `on(fn)` | 等价于 `bus.on('apps:changed', fn)` |

### `ctx.market`

| 方法 | 说明 |
|---|---|
| `load()` | 读 `store.json` 与本机覆盖 |
| `list(kind)` | 返回清单条目，并附 `installed` / `active` 状态 |
| `shell()` / `apps()` / `features()` / `ui()` | 解析当前生效 id 列表 |
| `setShell(id)` / `setWallpaper(id)` | 单选外壳/背景 |
| `wallpaper()` | 当前背景 id 或 `null`（跟随主题壁纸） |
| `themeId()` / `themes()` / `setTheme(id)` | 主题当前值与全集 |
| `install(id, kind)` / `uninstall(id, kind)` | 记录差量；`ui` 安装会按 `category` 自动卸掉同类 |
| `forget(id, kind)` | 从「后来装上」名单移除，用于加载失败自愈 |
| `reset()` | 清空本机商城覆盖 |
| `categoryOf(id)` | 读清单里的 `category` |
| `manifest()` / `raw()` | 清单原文 / 本机覆盖原文 |

### `ctx.people`

| 方法 | 说明 |
|---|---|
| `list()` / `get(id)` | 当前人物列表 / 单个 |
| `add(character)` / `update(id, patch)` / `remove(id)` | 增改删，全部写 `core/characters` 并发 `people:changed` |
| `reset()` | 删掉本机人物，恢复 `app.json.characters` |
| `load()` | 启动时加载；模块一般不需要调用 |

## 事件目录

| 事件 | 发出方 | payload | 典型用途 |
|---|---|---|---|
| `llm:ready` | `core/llm.js` 创建时 | `{}` | 预留 |
| `boot:done` | `assemble()` 尾部 | `{ apps: [id] }` | 启动完成后的外部钩子 |
| `apps:changed` | `core/apps.js` | `{ count }` | 外壳重画图标 |
| `app:opened` | `core/host.js` | `{ id }` | 统计/联动 |
| `app:closed` | `core/host.js` | `{ id }` | 统计/联动 |
| `settings:changed` | `core/settings.js` | `{ path, value }` | boot 监听 `theme*` 重新应用主题 |
| `people:changed` | `core/people.js` | `{ count }` | 聊天列表刷新 |
| `chat:replied` | `modules/app.chat` | `{ character, messages }` | 记忆模块据此累计轮数并摘要 |
| `memory:added` | `modules/memory.simple` | `{ characterId, text }` | 预留 |

事件是单向广播：不允许用事件做请求/响应，也不允许同步递归调用其他模块。

## 设置项注册表

模块在 `setup(ctx)` 里声明设置组：

```js
ctx.bus.settings.register({
  id: 'app.chat',
  title: '消息',
  fields: [
    {
      key: 'apps.chat.turns',
      label: '带几轮',
      type: 'number',
      min: 2,
      max: 40,
      hint: '最近多少轮进上下文',
    },
  ],
});
```

字段类型与行为：

| `type` | 控件 | 保存值 |
|---|---|---|
| `select` | 下拉框，`options: [[value, label]]` | 字符串 |
| `color` | 颜色选择器 | 十六进制字符串 |
| `range` | 滑块 | 数字 |
| `number` | 数字输入 | 数字（空值保存为 0） |
| `password` | 密码框；变更后清空输入并 toast | 通过自定义 `set` 保存，如 `settings.setKey` |
| 其他/缺省 | 文本输入 | 字符串 |

字段还可以带自定义 `get` / `set`：

```js
{
  key: 'ai.key',
  type: 'password',
  get: async () => '',
  set: (value) => settings.setKey(value),
}
```

设置页 `app.settings` 只遍历注册表，所以**加模块不需要改设置页**。

## 生命周期

```text
boot/assemble
   ├─ loadModule → injectCSS（如有 css）
   ├─ setup(ctx)        // 注册设置、提示词、事件；可异步
   └─ mount(...)        // 仅 shell/app：建 DOM，返回 { destroy }
                          shell: mount(stage, ctx, { apps })
                          app:   mount(body, ctx, api)

reboot / 关闭 App
   └─ destroy()         // 清定时器、事件、DOM
```

- `setup` 在每次 `assemble()` 都会重新执行，因此**不能假设只执行一次**。
- `mount` 在每次打开 App 时执行，关闭时 `destroy`。
- 功能模块当前没有统一的 `destroy` 回调；如果注册了 `bus` 监听，重装后会叠加（见第 14 页）。
- 外壳的 `mount` 返回实例，boot 只保存它用于下次重装时销毁。

## App 的 `api` 参数

`host.open()` 给 `app.mount(body, ctx, api)` 的第三个参数：

| 成员 | 说明 |
|---|---|
| `api.params` | `host.open(id, params)` 传入的参数对象 |
| `api.setTitle(text)` | 改页头标题 |
| `api.setSubtitle(text)` | 改副标题 |
| `api.setBack(fn, label)` | 接管返回键；不设则返回到桌面 |
| `api.close()` | 关闭当前 App 层 |

返回键由内核统一提供，应用内部的多级页面用 `setBack` 实现，不要自己再造一套顶部导航（除非外壳/应用有意覆盖）。

## 模块作者最常犯的错

- 在模块里 `import` 内核文件 → 破坏可拆卸性。
- 在 `setup` 里注册 `bus` 监听却不清理 → 重装后重复执行。
- 把「当前有哪些 App」存成数组快照 → 后加的 App 永远不显示；必须订阅 `apps:changed`。
- 直接改别人的命名空间 → 卸载/导入时互相污染。
- 写死颜色 → 换主题时只有它不跟着变。
- 在外壳里重复实现 `.stage` 的宽屏收窄 → 内核已经统一处理。
- 把模块专属类名加进 `core/styles.css` → 内核膨胀且样式互相干扰。
