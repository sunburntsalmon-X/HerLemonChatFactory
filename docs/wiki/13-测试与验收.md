# 13 · 测试与验收

相关文件：`tests/*.mjs`、`tests/package.json`、`tests/package-lock.json`。

## 准备

```bash
cd tests
npm ci      # 按 lockfile 安装，避免依赖版本漂移
npm test
```

依赖只有两个开发依赖：

- `jsdom@^25`：伪造 DOM、事件、`getComputedStyle`、资源加载。
- `fake-indexeddb@^6`：在 Node 里提供 IndexedDB。

根目录没有 `package.json`；应用运行不依赖 npm 包。

## `npm test` 跑什么

`tests/package.json` 的 test 脚本按固定顺序串行执行 11 个文件：

```text
smoke → swap → market → contacts → memory → wallpaper
      → registry → stale → ui → shop → sheet
```

任何一个文件 `process.exit(1)`，整条链就停在那里。

## 测试环境怎么搭

大多数脚本的骨架一致：

```js
const dom = new JSDOM('<!DOCTYPE html><html><body><div id="app"></div></body></html>', {
  url: 'http://localhost/',
  pretendToBeVisual: true,
});
```

然后把 `window`、`document`、`Node`、`HTMLElement`、`localStorage`、`requestAnimationFrame` 等桥接到 `globalThis`。

`fetch` 被替换成本地文件读取桩：

```js
globalThis.fetch = async (url) => {
  const file = path.join(APP, String(url).replace(/^\.\//, ''));
  const text = await readFile(file, 'utf8');
  return { ok: true, status: 200, json: async () => JSON.parse(text), text: async () => text };
};
```

所以：

- `boot.js` 能读到 `app.json`、`store.json`。
- 模块里的真实网络请求会失败；测试必须走演示模式。
- `registry.mjs` 会在桩里动态往 `app.json` / `store.json` 注入临时应用 `app.probe`，并在结束时删除 `modules/app.probe`。如果测试中断，可能留下该目录，手动删掉即可。

`ui.mjs`、`shop.mjs`、`sheet.mjs` 额外用 `ResourceLoader` 真正加载 CSS，因为要断言 `getComputedStyle` 的边框、对齐方式。其他脚本不加载 CSS。

## 断言风格

测试尽量断言「用户看得见的结果」，而不是内部实现：

- 桌面图标数量与名字。
- `.shop-card`、`.bubble`、`.sheet-mask`、`.sidebar-list` 等 DOM 是否存在。
- CSS 变量值、`getComputedStyle` 的 `borderTopWidth` / `alignItems` / `justifyContent`。
- 数据仓里的键是否存在、数量是否正确。

这保证重构内部实现时，测试仍然有意义。

## 测试的边界

- **不是真浏览器**：jsdom 没有真实布局、滚动、动画；涉及视觉的断言只能看计算样式。
- **没有真实网络**：LLM 只走 mock。
- **时序靠 `sleep`**：不同机器上可能偶发不稳；新增测试尽量等待明确条件，而不是固定长睡眠。
- **串行执行**：一个测试失败会阻断后面的测试。
- **不覆盖重装后的监听叠加**：`memory.simple` 在 `reboot` 后重复注册监听的问题目前没有测试（见第 14 页）。

## 新增一个测试

1. 复制一个现有脚本作为骨架。
2. 配好 JSDOM、全局桥接、`fetch` 桩。
3. `await import(path.join(APP, 'core/boot.js'))`，等 `data-booted="1"`。
4. 用 DOM 操作模拟用户路径，断言可见结果。
5. 把文件名加进 `tests/package.json` 的 `test` 链。
6. 单独运行：`node tests/<name>.mjs`。

## 改动后的最低验收

- 改内核：11 个测试全绿。
- 加模块：11 个测试全绿，并至少新增一条覆盖该模块可见行为的测试。
- 只改文案/样式：至少跑 `smoke.mjs` 与受影响的视觉测试（`ui` / `shop` / `sheet` / `market`）。
