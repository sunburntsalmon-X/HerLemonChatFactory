# 08 · 应用容器与外壳

相关文件：`core/host.js`、`core/apps.js`、`modules/shell.grid`、`modules/shell.asael`、`modules/shell.sidebar`、`core/styles.css` 的「外壳容器」「App 容器」两节。

## 职责切分

| 角色 | 负责 | 不负责 |
|---|---|---|
| `host` | 打开/关闭 App、页面层、返回栈、错误兜底 | 桌面长什么样 |
| `apps` 注册表 | 当前有哪些 App、变更广播 | 图标怎么画 |
| 外壳 | 画桌面、画图标、把点击变成 `host.open()` | App 内部逻辑、返回栈 |
| App | 自己的页面与数据 | 桌面、外壳、其他 App |

## `host.open(id, params)`

打开一个 App 时创建：

```text
<div class="app-layer">
  <div class="app-header">
    <button class="btn-back">‹ 返回</button>
    <div>
      <h1>应用名</h1>
      <div class="sub"></div>
    </div>
  </div>
  <div class="app-body"></div>
</div>
```

流程：

1. 从 `apps.get(id)` 取模块；没有 `mount` 直接返回。
2. 建层、页头、返回键、内容区，挂到 `stage`。
3. 建 `api`：`params`、`setTitle`、`setSubtitle`、`setBack`、`close`。
4. 入栈 `{ layer, instance, id }`。
5. `app.mount(body, ctx, api)`；抛错则渲染 `.error-card`，页面其余部分仍在。
6. 发 `app:opened`。
7. 返回 `instance`。

`api.setBack(fn, label)` 的行为：

- 不设 `fn`：返回键调用当前层的 `close()`（关掉 App，回到桌面）。
- 设了 `fn`：返回键只执行 `fn`，不关闭 App；常用于列表 ↔ 详情这种内部导航。
- `label` 只改返回键文字。

`close()`：

1. 从栈里移除自己。
2. 调 `instance.destroy?.()`。
3. 移除 DOM 层。
4. 发 `app:closed`。

### 多层的实际情况

`host.open()` 只追加层，不自动关闭已经打开的应用。外壳在桌面点击时通常只有一层，所以日常不会叠；但模块如果在一个 App 里再次调用 `ctx.host.open()`，会出现两层 App 同时存在。需要返回时由调用方自己管理。

`host.reset()` 在重装前从栈顶往下逐个销毁并移除，然后 `apps.clear()`。

`host.closeAll()` 会销毁并移除所有层，但不会逐个发 `app:closed`；当前仓库没有使用它。

### App 页头

页头由内核统一提供，包含标题、副标题、返回键。应用可以通过 `api.setTitle` / `setSubtitle` 改文字，通过 `api.setBack` 改返回行为。

内核不提供状态栏、电量、信号等「假手机」元素；需要的话由外壳实现。

## `apps` 注册表

`core/apps.js` 是「当前有哪些 App」的唯一来源：

```js
apps.register(mod)  // 有 id 才能注册，注册后发 apps:changed
apps.remove(id)
apps.get(id)
apps.list()
apps.clear()        // 不发事件
apps.on(fn)         // = bus.on('apps:changed', fn)
```

两种注册方式：

| 方式 | 谁用 | 行为 |
|---|---|---|
| `boot` 对 `market.apps()` 里的模块调用 `ctx.apps.register(mod)` | 配置应用、商城安装的应用 | 自动入册 |
| 模块主动调用 `ctx.host.registerApp({...})` | 功能模块自带的 App（`memory.simple`） | 等价于 `apps.register` |

外壳必须订阅 `apps:changed` 重画，不能只在启动时取一次数组。旧实现就是因为存了快照，后加的应用永远不显示。

## 三种外壳

所有外壳的 `mount` 签名：

```js
mount(stage, ctx, { apps }) {
  // 画桌面
  return { destroy() { /* 取消订阅、移除 DOM */ } };
}
```

`stage` 是内核提供的 `.stage` 容器；宽屏收窄成 420px 手机的逻辑在 `core/styles.css` 的 `.stage` 里，外壳不要重复实现。

### `shell.grid`

```text
.desktop
└─ .icon-grid
   └─ button.appicon（.tile + small）
```

- 4 列网格。
- 只有图标，没有状态栏和标题。
- 订阅 `apps.on(render)`，App 增减时整组重画。
- `destroy` 取消订阅并移除 `.desktop`。

### `shell.asael`

```text
.phone-home
├─ .phone-scroll
│  └─ .icon-grid（除 Dock 常驻外的应用）
└─ .phone-dock
   └─ appicon × 3 + 空槽补齐到 4
```

- Dock 固定：`app.store`、`app.settings`、`app.contacts`。
- 玻璃质感图标、顶部反光、Dock 毛玻璃全部写在模块自己的 `style.css`。
- 即使 Dock 应用被卸载，Dock 也不会崩；只是对应位置空出来。

### `shell.sidebar`

```text
.sidebar
├─ .sidebar-list（每个 App 一行：小图标 + 名字）
└─ .sidebar-body（默认显示「侧边栏外壳」与人物/应用数量）
```

- 点击侧栏项调用 `ctx.host.open(app.id)`。
- `render` 同时更新侧栏和右侧统计。
- `destroy` 取消订阅并移除 `.sidebar`。

### 外壳的样式边界

- 内核**不定义** `.desktop`、`.icon-grid`、`.appicon`、`.tile`、`.phone-dock`、`.sidebar-*`。
- 每个外壳自带一整套桌面样式；允许外壳之间重复这些类名，因为它们不会同时生效。
- 切换外壳时，boot 会移除不再生效的模块 CSS，所以旧外壳样式不会残留（代价是每个外壳要自己写全）。
- 想统一外观，应做一个 UI 模块让大家依赖，而不是把桌面样式塞回内核。

## 新增一个外壳

1. 新建 `modules/shell.<name>/index.js`。
2. `kind: 'shell'`，`api: '1.x'`，`css: 'style.css'`。
3. `mount(stage, ctx, { apps })` 画自己的桌面，并订阅 `apps.on(...)`。
4. 图标点击调用 `ctx.host.open(app.id)`。
5. 返回 `{ destroy }`，取消订阅并移除根节点。
6. 在 `store.json.modules` 加一条 `kind: 'shell'`，商店「桌面」分组就会出现。
7. 想设为默认，改 `app.json.shell`。

完整模板见 [11-模块开发指南](11-模块开发指南.md)。

## 常见坑

- **只改 `mount` 不订阅 `apps:changed`**：启动后新装的应用不出现。
- **把 App 列表存成数组传进外壳**：同上，违反注册表模式。
- **在外壳里管返回栈**：返回是 `host` 的职责。
- **把桌面样式写进 `core/styles.css`**：切换外壳时只有排布变、外观不变，是历史踩过的坑。
- **`.stage` 上乱挂节点**：只有背景类模块可以碰，且必须带 `data-module-owned`，否则重装后清不掉。
