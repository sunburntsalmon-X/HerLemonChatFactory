# 03 · 启动与装配

相关文件：`index.html`、`core/boot.js`、`core/host.js`、`core/market.js`。

## 入口

`index.html` 只做三件事：

1. 提供 `<div id="app">`。
2. 加载内核样式 `./core/styles.css?v=6`。
3. 以 ES Module 加载 `./core/boot.js?v=6`。

`boot.js` 里的缓存号：

```js
const VER = '6';
```

改完内核资源后必须同时提升 `index.html` 的 `?v=` 和 `boot.js` 的 `VER`，否则浏览器可能继续用旧模块。`VER` 同时用于：

- 内核自身所有 `import(..., ?v=VER)`。
- 模块入口 `modules/<id>/index.js?v=VER`。
- 模块样式 `<link href=".../style.css?v=VER">`。

## 一次启动的完整流程

`boot()` 的顺序是固定的：

1. **读配置**：`fetch('./app.json', { cache: 'no-cache' })`，失败直接进入致命错误页。
2. **建数据仓**：`createVault()`，优先 IndexedDB，失败退回 `localStorage`。
3. **建事件总线**：`createBus()`。
4. **建并加载设置**：`createSettings({ defaults: config, vault, bus })` → `settings.load()`。
   - 本机保存的 `core/settings` 会深度合并到 `app.json` 默认值上。
5. **建并加载商城**：`createMarket({ vault, config })` → `market.load()`。
   - 读 `store.json`，读本机 `core/market` 覆盖，迁移旧快照，清掉不存在的背景模块引用。
6. **建并加载人物**：`createPeople({ vault, config, bus })`。
7. **建 `stage` 容器**：`<div class="stage">`，清空 `#app` 后挂入。
8. **应用主题**：`themeNow()` 合并「主题预设 + 设置里的强调色/圆角」，`applyTheme(theme, stage)`。
9. **创建其余内核服务**：`prompt`、`llm`、`apps`（注册表）、`host`（容器）。
10. **组装 `ctx`**：把上面所有服务、`stage`、`reboot`、`ui`、`applyTheme` 放进同一个对象。
11. **`host.setContext(ctx)`**：让 `host.open()` 能把 `ctx` 传给 App 的 `mount`。
12. **注册内核设置组**：`core.ai`（模型）、`core.theme`（外观）。
13. **监听主题设置**：`settings:changed` 且路径以 `theme` 开头时重新 `applyTheme()`。
14. **`await assemble()`**：装配所有模块。
15. **标记启动完成**：`document.documentElement.dataset.booted = '1'`。

任何一步抛错都会进入 `fatal(err)`：清空页面并渲染 `.error-card`，提示截图给助手。

## `assemble()` 的装配顺序

```text
1. 销毁旧外壳（shellInstance.destroy）
2. 清掉 stage 上 data-module-owned 的节点（背景层等）
3. host.reset()        → 卸载所有 App 层 + 清空 App 注册表
4. apps.clear()        → 再清一次（host.reset 内部也清）
5. prompt.reset()      → 清空提示词贡献者，避免人设拼两遍
6. UI 模块（market.ui()）      setup
7. 角色脑子（人物 runtime 去重） setup
8. 应用（market.apps()）       setup + apps.register
9. 功能（market.features()）   setup
10. 清理不再生效的模块 CSS <link>
11. 装外壳：setup + mount(stage, ctx, { apps })
12. emit('boot:done', { apps: [...] })
```

顺序不是随意的：

- **UI 最先**：UI 模块只有样式，先插 `<link>`，它的样式表就排在应用自带 CSS 前面，应用能覆盖皮肤（设计决策 D19）。
- **角色脑子先于应用**：聊天应用在 `mount` 时依赖 `runtime` 已经向提示词管线注册好人设段。
- **应用先于功能**：功能模块可能通过 `host.registerApp()` 自带 App；先注册配置里的应用，功能 App 就排在后面。
- **外壳最后**：桌面要等 App 注册表稳定后再画。

装配完成后，生效模块集合为：

```text
market.ui() + runtime 集合 + market.apps() + market.features() + market.shell()
```

所有 `link[data-module^="module-css:"]` 里不在该集合的样式会被移除。这样切换外壳、卸载应用、卸下 UI 皮肤后不会残留旧样式。

## 模块加载与校验

`loadModule(id)`：

```js
if (!id || !/^[a-z][\w.-]*$/i.test(id)) throw new Error(`非法的模块 id：${id}`);
const mod = await import(`../modules/${id}/index.js?v=${VER}`);
const m = mod.default;
if (!m) throw new Error(`${id} 没有 default 导出`);
if (m.api !== '1.x') throw new Error(`${id} 要求 api ${m.api}，当前是 1.x`);
if (m.css) injectCSS(id, m.css);
return m;
```

因此模块必须：

- 目录名合法；
- `export default` 一个对象；
- 声明 `api: '1.x'`；
- 如果需要样式，声明 `css: 'style.css'`。

`injectCSS` 只插一次：如果页面已有 `link[data-module="module-css:<id>"]` 就跳过。

## 装配失败时

| 失败对象 | 处理 |
|---|---|
| UI 模块 | `console.error` + `market.forget(id, 'ui')` + toast「已经用不了了，已从名单里移除」 |
| 角色脑子 | 只 toast「装载失败」，不摘除（人物还引用它） |
| 应用 | `market.forget(id, 'app')` + toast |
| 功能 | `market.forget(id, 'feature')` + toast |
| 外壳 | catch 后在 stage 上渲染「外壳没能启动」错误卡，内核本身还在 |

`market.forget()` 只从本机「后来装上的」名单里移除；如果是 `app.json` 自带的应用加载失败，它不会改 `app.json`，下次启动仍会再试。

## 原地重装 `reboot(reopen)`

商城的换桌面、装/卸应用、装/卸界面皮肤都走这一条：

```js
async function reboot(reopen) {
  if (assembling) return;
  assembling = true;
  try {
    await assemble();
    if (reopen) ctx.host.open(reopen);
  } catch (err) {
    ...
  } finally {
    assembling = false;
  }
}
```

关键行为：

- **不刷新页面**：只销毁并重建模块层。
- **商店自己还开着**：商城调用 `ctx.reboot('app.store')`，重装完自动重新打开商店。
- **防重入**：`assembling` 为真时忽略新的重装请求。
- **旧外壳先销毁**：`shellInstance?.destroy?.()`。
- **背景层先清掉**：所有带 `data-module-owned` 的节点会被移除，避免重复叠背景。

## 换主题为什么不重装

主题不是模块，只改 CSS 变量：

```text
market.setTheme(id) → settings.set('theme.accent', null) → ctx.applyTheme()
```

不经过 `assemble()`，所以商店、聊天都保持当前状态，只换颜色。

## 启动链示意图

```text
index.html
   │
   ▼
boot.js
   ├─ fetch app.json
   ├─ vault / bus / settings / market / people
   ├─ stage + applyTheme
   ├─ prompt / llm / apps / host
   ├─ ctx 组装 + 内核设置注册
   └─ assemble()
        ├─ UI 模块
        ├─ runtime
        ├─ apps  → apps.register → apps:changed → 外壳重画
        ├─ features
        ├─ 清理失效 CSS
        └─ shell.mount(stage, ctx, { apps })
```

## 改内核时的注意事项

- `assemble()` 里新增/调整顺序，必须同步 `AGENTS.md` 与本页。
- 任何重装路径都必须先 `prompt.reset()`，否则提示词贡献者会重复。
- `host.reset()` 会清空 App 注册表；重装前不清会残留旧 App。
- `boot` 只给外壳传 `ctx.apps` 注册表，不要改成一启动就传数组快照。
- 新增“模块往 stage 挂东西”的能力时，节点必须带 `data-module-owned`，并接受重装清理。
