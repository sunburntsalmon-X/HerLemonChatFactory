# 07 · 聊天与记忆

相关文件：`modules/app.chat/index.js`、`modules/memory.simple/index.js`、`core/prompt.js`、`core/llm.js`。

## `app.chat`：消息应用

### 结构

```text
消息列表（people.list() 中每个人一行）
   │ 点一行
   ▼
对话页
   ├─ 历史消息气泡
   ├─ 输入框（textarea，自适应高度）
   └─ 发送按钮
```

应用本身不认识桌面和外壳；它只通过 `ctx` 拿 `people`、`vault`、`prompt`、`llm`、`bus`、`settings`、`ui`。

### 会话列表

每次进入列表：

1. 遍历 `people.list()`。
2. 从 `app.chat` 命名空间读 `conv:<id>`。
3. 预览取最后一条消息内容（压缩空白）；没有记录时显示开场白或「还没聊过」。

列表没有按时间排序，顺序就是人物列表顺序。

### 打开对话

```js
const saved = await store.get(`conv:${ch.id}`, null);
if (Array.isArray(saved) && saved.length) {
  messages = saved;
} else {
  messages = [{ role: 'assistant', content: ch.greeting || '……', ts: Date.now() }];
  await save();
}
```

- 第一次进入会把开场白作为 assistant 消息落盘。
- 返回键被 `api.setBack` 接管：先中断正在流式的请求，再回到列表。

### 发送与回复

```text
用户输入
  → push { role: 'user', content, ts }
  → 立即上屏 + save()
  → reply()
       ├─ 追加一个 .bubble.ai.typing 占位
       ├─ 取最近 turns*2 条 history
       ├─ prompt.build({ character, history, userText, settings }, budget)
       ├─ ctx.llm.stream({ character, messages: history, system, signal })
       ├─ 逐段追加到气泡
       └─ 结束后保存 assistant 消息，并发 chat:replied
```

保存时机：

- 用户消息发出后立即保存。
- 回复结束后，若收到非空文本，再保存 assistant 消息。
- 出错或中断时，若已收到部分文本，也会保存部分内容。

### 消息格式

```js
{ role: 'user' | 'assistant', content: '...', ts: 1730000000000 }
```

传给模型前会剥掉 `ts`。

### 返回栈

- 列表页：`api.setBack(null)`，返回键由内核处理（回桌面）。
- 对话页：`api.setBack(showList, '‹ 消息')`，返回键先回列表。
- `destroy()`：取消 `people:changed` 订阅，并 `abort.abort()`。

### 事件

回复完成后：

```js
ctx.bus.emit('chat:replied', {
  character: current,
  messages: messages.slice(),
});
```

这是记忆模块唯一的触发点；聊天应用完全不知道记忆的存在。

## `memory.simple`：简单记忆

### 定位

一个 `feature` 模块，只使用 `ctx` 的 `vault`、`prompt`、`bus`、`settings`，内核没有为它改过一行。它做两件事：

1. 每聊 N 轮，把最近对话压成一条记忆，按人物分开存。
2. 每次开口前，挑几条相关记忆投进提示词管线。

它还通过 `ctx.host.registerApp()` 自带一个「记忆」App，因此桌面会多一个图标，但 `app.json.apps` 里没有它。

### 设置项

| 键 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `memory.simple.every` | 3 | 2–20 | 每几轮摘要一次 |
| `memory.simple.recall` | 4 | 1–10 | 每次带几条进上下文 |
| `memory.simple.keep` | 60 | 10–300 | 每个人最多存多少条 |

### 数据

| 键 | 内容 |
|---|---|
| `items:<characterId>` | `[{ id: 'm...', text, at }]` |
| `turns:<characterId>` | 距下次摘要的累计轮数 |

`setup()` 时会为当前每个人物加载缓存，并恢复未完成的计数。

### 计数与摘要

订阅 `chat:replied`：

```text
count = 该人物已累计轮数 + 1
写回 turns:<id>
if count < every: 返回
count 归零
remember(character, messages)
```

`remember()`：

1. 取最近 8 条消息。
2. `summarize()`：
   - `provider === 'mock'` 或没有密钥：本地提取。
   - 否则调用 `ctx.llm.stream()`，system 为 `SUMMARY_PROMPT`，要求 40 字以内、只记用户事实/偏好/约定，没得记就回复「无」。
   - 返回文本去掉首尾引号、截到 60 字；以「无」开头则丢弃。
3. 去重：已有记忆与新文本互相包含时跳过。
4. push `{ id, text, at }`，只保留最后 `keep` 条。
5. 写回 `items:<id>`，发 `memory:added`。

本地提取（演示模式也能工作）：

```text
用户提到过：<倒数第二条用户消息前 20 字>；<最后一条用户消息前 20 字>
```

### 召回

`prompt.register` 的 `build`：

1. 取该人物的全部记忆。
2. 用 `rank(items, userText)` 排序，取前 `recall` 条。
3. 没有记忆时返回空串（该段不参与拼装）。
4. 有记忆时输出：

```text
你记得这些事（自然地用，不要照念）：
- ...
- ...
```

`rank()` 不引入任何依赖：

- 把查询去掉空白、标点、符号，切成相邻二字组（bigram）。
- 命中比例 `overlap = 命中 bigram 数 / 查询 bigram 总数`。
- 时间衰减 `exp(-天数 / 21)`。
- 得分 `overlap * 2 + 时间衰减`，降序。

这是「最近 + 关键字」召回，不是向量检索。

### 记忆 App

`setup` 里注册：

```js
ctx.host.registerApp({
  id: 'app.memory',
  kind: 'app',
  api: '1.x',
  meta: { name: '记忆', icon: '🧠', color: 'var(--accent)' },
  mount(body, _, api) { ... },
});
```

页面：

- 按人物分组显示条数与全部记忆（倒序）。
- 单条「删」。
- 「清空全部记忆」（确认后逐人物写空数组）。
- 底部显示当前「每 N 轮、带 M 条」。
- 没有记忆时显示空状态。

删除人物后，记忆仍留在 `memory.simple` 命名空间里；如果以后新建同 id 的人物，旧记忆会重新出现。

## 两条主线的交汇

```text
app.chat.reply()
   ├─ ctx.prompt.build() ← runtime.chat 的人设段
   │                     ← memory.simple 的记忆段
   ├─ ctx.llm.stream()
   └─ emit('chat:replied')
          └─ memory.simple 计数 → 到点摘要 → 写 items:<id>
```

记忆模块不直接读聊天记录，聊天应用也不直接读记忆；两者只通过提示词管线和 `chat:replied` 事件接触。

## 当前实现的注意点

- **重装后监听会叠加**：`memory.simple` 在 `setup()` 里 `ctx.bus.on('chat:replied', ...)`，但没有对应的 `destroy` / 取消订阅。`reboot()`（换桌面、装卸应用）会再次执行 `setup`，旧的监听仍然存在。实际表现可能是：切换一次桌面后，每回复一次会计多轮、摘要多次。新增 feature 模块时不要复制这个模式，至少把取消函数存起来并在合适的卸载时机调用。
- `memory.simple` 的 `setup` 是异步的；它先 `await loadAll()` 再注册提示词与监听。启动阶段会等待它完成。
- 记忆摘要与聊天回复共用 `ctx.llm`，但摘要没有传 `signal`，无法中止。
- 只有「最近 + 二元字组」召回，没有 embedding；替换方案应新写 `memory.*` 模块，而不是改内核。
