# 05 · 数据与备份

相关文件：`core/vault.js`、`core/settings.js`、`core/people.js`、`core/market.js`、`modules/app.settings/index.js`。

## `vault`：唯一的数据入口

所有模块数据都走 `ctx.vault`，不直接碰 `localStorage` 或 `indexedDB`。

### 后端选择

1. 启动时尝试打开 IndexedDB：
   - 数据库：`xiaoshouji`
   - 对象仓库：`kv`
   - 版本：1
2. 失败（隐私模式、浏览器禁用了 IndexedDB、被占用）则退回 `localStorage`：
   - 键前缀：`xsj\u0000`
   - 值：`JSON.stringify` 后的字符串

对调用方来说接口一致，只是性能与容量不同。控制台会出现 `[vault] IndexedDB 不可用，退回 localStorage`。

### 键的物理格式

```text
<namespace>\u0000<key>
```

例如：

- `core\u0000settings`
- `app.chat\u0000conv:ayan`
- `memory.simple\u0000items:ayan`

`namespace(ns)` 返回的句柄会自动加前缀，所以模块只写逻辑键：

```js
const store = ctx.vault.namespace('app.chat');
await store.set('conv:ayan', messages);
const saved = await store.get('conv:ayan', []);
```

### API

| 方法 | 说明 |
|---|---|
| `namespace(ns)` | 取命名空间；`ns` 必须是字符串 |
| `ns.get(key, fallback)` | 读不到时返回 `fallback` |
| `ns.set(key, value)` | 写入（结构化数据直接存对象） |
| `ns.del(key)` | 删除单个键 |
| `ns.keys()` | 该命名空间下的逻辑键列表 |
| `vault.exportAll()` | 按命名空间分组导出 `{ ns: { key: value } }` |
| `vault.importAll(data, { merge })` | 默认先清空再导入；`merge: true` 时保留旧数据 |
| `vault.clearAll()` | 清空全部数据 |

> 命名空间隔离是**约定**，不是强制：`namespace('x')` 不会阻止你写 `x\u0000...` 以外的键。模块必须自律。

## 当前数据清单

| 命名空间 | 键 | 写入方 | 内容 |
|---|---|---|---|
| `core` | `settings` | `core/settings.js` | 整份配置（不含 `characters`）；含 `apps`、`shell`、`features`、`theme`、`ai` 等 |
| `core` | `market` | `core/market.js` | 商城本机覆盖：`shell`、`wallpaper`、`theme`、`added`、`removed`、`featuresAdded`、`featuresRemoved`、`uiAdded`、`uiRemoved` |
| `core` | `characters` | `core/people.js` | 用户改过的人物数组；删除该键即恢复出厂人物 |
| `core` | `ai.key` | `core/settings.js` | API 密钥明文（仅本机） |
| `app.chat` | `conv:<characterId>` | `modules/app.chat` | 该人物的消息数组，元素为 `{ role, content, ts }` |
| `memory.simple` | `items:<characterId>` | `modules/memory.simple` | 该人物的记忆数组，元素为 `{ id, text, at }` |
| `memory.simple` | `turns:<characterId>` | `modules/memory.simple` | 距上次摘要累计的轮数 |
| `fx.bg.theme` | `config` | `modules/fx.bg.theme` | `{ template }` |
| `fx.bg.image` | `config` | `modules/fx.bg.image` | `{ image, filter, blur, opacity }` |
| `fx.bg.css` | `config` | `modules/fx.bg.css` | `{ css }` |

人物本身不在 `app.chat` 里，聊天记录也不在 `memory.simple` 里；删除人物不会删除对话记录。

## `settings`：默认值 + 本机覆盖

### 读取

```js
const settings = createSettings({ defaults: config, vault, bus });
await settings.load();
// 本机 core/settings 深度合并到 app.json 默认值
```

- 点路径读取：`settings.get('ai.params.maxChars', 2000)`。
- `settings.all()` 返回的是内存对象引用；`ctx.config` 就是它。

### 写入

```js
await settings.set('apps.chat.turns', 20);
```

行为：

1. 按点路径写入内存对象（自动创建中间对象）。
2. `persistable(values)` 去掉 `characters` 后，把**整份配置**写入 `core/settings`。
3. 发 `settings:changed`，`boot` 据此在 `theme*` 变化时重新应用主题。

### 一个需要注意的副作用

因为持久化的是整份配置（除人物），用户只要改过任意设置或换过主题（商城换主题会调用 `settings.set('theme.accent', null)`），`core/settings` 里就会存下当时的 `apps` / `features` / `shell` 等字段。

之后如果仓库里的 `app.json` 新增了应用或改了默认外壳，`load()` 的深度合并会用本机旧值覆盖新默认值，导致新增项不出现。开发时验证 `app.json` 改动的建议：

- 先在设置里「清空本机数据」，或
- 删除 `core/settings` 键，或
- 只改 `app.json` 前确认本机没有设置快照。

这不是当前测试覆盖的路径；详见 [14-文档缺口与待办](14-文档缺口与待办.md)。

### 密钥

- `setKey(secret)` 写 `core/ai.key`，`getKey()` 读。
- 密钥不写入 `core/settings`，也不写入 `app.json`。
- 设置页的密码框每次显示为空，只允许覆盖写入。

## `market`：差量覆盖而不是快照

`core/market` 存的是「用户在出厂配置之上做了什么」：

```js
{
  shell: null,          // 当前外壳；null 表示跟 app.json
  wallpaper: null,      // 当前背景 App；null 表示跟随主题壁纸
  theme: null,          // 当前主题；null 表示跟 app.json.theme.preset
  added: [],            // 后来安装的应用
  removed: [],          // 后来卸载的出厂应用
  featuresAdded: [],
  featuresRemoved: [],
  uiAdded: [],
  uiRemoved: [],
}
```

生效列表的解析公式：

```text
生效 = app.json 列表 − removed + added
```

应用、功能、界面皮肤各有一对 `added/removed`；外壳、背景、主题是单选字段。

旧版本曾把整份 App 列表存成快照，`market.load()` 里的 `migrate()` 会把旧 `apps` 数组转换成差量，原则是「只补不删」：宁可让用户删过的应用回来一次，也不把没见过的应用误判成已删。

## 备份：真实实现

### 导出

设置 → 数据 → 「导出备份」：

```js
{
  format: 'xiaoshouji-backup',
  version: 1,
  at: '2026-...',
  characters: settings.get('characters', []),  // app.json 里的出厂人物
  data: await vault.exportAll(),               // 全部命名空间
}
```

下载为 `xiaoshouji-<timestamp>.json`。

注意：

- `characters` 顶层字段是 `app.json` 的出厂人物，不是用户修改后的本机人物。
- 用户人物实际在 `data.core.characters` 里，所以正常备份仍能恢复本机人物。
- 背景图片是 data URL，会一起进入 `data.fx.bg.image.config.image`，备份文件可能很大。

### 导入

设置 → 数据 → 「导入备份」：

1. 读 JSON。
2. `const data = payload.data || payload;`（兼容直接导出的命名空间对象）。
3. 弹确认框「导入会覆盖本机现在的对话」。
4. `vault.importAll(data, { merge: false })`：**先清空全部数据**，再写入。
5. 600ms 后 `location.reload()`。

当前**没有**实现旧文档里描述的这些能力：

- 模块不在时的「暂存区」；
- 按 schema 版本跑模块迁移；
- schema 更新的「请先升级」拦截；
- 导入前自动备份旧数据。

导入就是覆盖。详见第 14 页。

## 重置的三种粒度

| 操作 | 入口 | 行为 |
|---|---|---|
| 恢复默认人物 | 通讯录 → 「恢复默认」 | 删除 `core/characters`，回到 `app.json.characters`；对话记录不动 |
| 清空商城选择 | 代码 `market.reset()` | 删除 `core/market`，外壳/背景/主题/装删记录回到出厂 |
| 清空本机数据 | 设置 → 「清空本机数据」 | `vault.clearAll()` 后刷新；人物、对话、记忆、设置、密钥全没 |

「恢复默认人物」和「清空本机数据」不是一回事，不要混用。

## 隐私与容量

- 所有数据都在当前浏览器，没有服务端同步。
- 图片背景在保存前压到 1440 长边、JPEG 质量 0.82，仍以 data URL 存在 IndexedDB 里。
- IndexedDB 容量通常远大于 localStorage；退回 localStorage 时，大图和长对话更容易超限。
- 密钥明文存在本机 IndexedDB；公开仓库不会泄露，但共用设备需要注意。
